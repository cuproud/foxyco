## Current device retest: Google Sign-In resource-shrinker fix

Device result on the upload-key-signed release APK:

1. Wizard opens correctly.
2. Driver taps **Start your 7-day free trial**.
3. The Google account chooser appears.
4. Selecting the account does not start the trial.
5. The old APK only showed:
   `Couldn't start the trial. Check your connection and retry.`

The diagnostic build then exposed:

`google/clientConfigurationError`

Root cause was in the release artifact, not the Firebase console: Android's
resource shrinker considered the generated `default_web_client_id` unreachable.
`google_sign_in_android` resolves that string by name at runtime, which R8
cannot detect, so the release APK lost the web OAuth client ID after the Google
account chooser appeared.

Fixed by `android/app/src/main/res/raw/keep.xml`, which explicitly retains
`@string/default_web_client_id`. The rebuilt APK was inspected with `aapt2`:
the final packaged resource now contains the expected web client ID, and R8's
`resources.txt` reports it as `reachable from keep xml file`.

The next device attempt reached Firebase Auth and exposed
`auth/provider-already-linked`. This means Google linking had succeeded during
an earlier attempt, but retrying called `linkWithCredential` on the already
Google-backed user. `TrialStore.startTrial` is now idempotent: it links only an
anonymous user; an existing non-anonymous session signs into the account just
selected and continues to the Firestore trial document.

The following attempt exposed `cloud_firestore/unavailable`. Console inspection
showed that Cloud Firestore had not actually been created. The `(default)`
Standard-edition database was created in Toronto (`northamerica-northeast2`),
production mode, and the repository's write-once trial rules were published.
The next trial attempt succeeded.

exception messages do not.

Possible tags include:

- `google/<code>` for Google authorization/configuration.
- `auth/<code>` for Firebase Authentication/linking.
- `cloud_firestore/<code>` for Firestore/database rules.
- `timestamp-pending` if a new server timestamp does not resolve immediately.
- `firebase-down`, `no-id-token`, or `no-user-after-signin` for setup/state.

The prior generic UI collapsed several possible errors:

- Google Auth audience/test-user denial.
- Google provider or Anonymous provider disabled in Firebase Auth.
- Google Sign-In Android configuration failure.
- Firebase Auth credential linking failure.
- Firestore database/rules failure after sign-in.

Because the chooser now appears, the failure may be in Google authorization,
Firebase credential linking, or the Firestore create/read that follows it.
